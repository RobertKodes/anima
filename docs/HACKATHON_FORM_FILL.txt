--- What breaks when memory is deleted? ---
Without memory, our agent forgets the user's name, relationships, goals, and stored policies — and the product becomes a generic chatbot that will approve Base spends it previously refused and cannot maintain identity across sessions or brain swaps.


--- Memory walkthrough (3 lines — judges score 40% from this) ---

Persist:
We persist self-model (name, values), people, goals, Base spending policies, journal episodes, and sleep consolidation into Sibyl via set_entity and write_event — no MEMORY.md or prompt files.

Recall (fresh session):
On every turn retrieval.py queries Sibyl FTS5 + entities before the LLM runs; after /new-session or restart with empty model context, "do you remember me?" and /memory search still return the taught name and facts.

Changes the agent's decision by:
A remembered 0-wei Base cap stored in Sibyl blocks on-chain spends after context is cleared; anima --amnesia disables retrieval so the same prompt gets newborn replies while the SQLite file stays on disk — proving memory is load-bearing, not decorative.


--- Memory primitives you used (bifează în formular) ---

☑ recall              — retrieval.py builds context package before every reply
☑ entities            — self/being, person/*, goal/*, policy/* via set_entity
☑ semantic search     — Sibyl FTS5 search + /memory search + anima-sibyl MCP
☑ temporal / time-travel — journal read_events with timestamps; /memory recent
☑ summarization       — /sleep consolidation; Sibyl learn(mode=local-deterministic)
☑ reflection          — /why traces memories and brains; /sibyl lint
☑ consolidation       — sleep cycle writes strategies and inspectable dream state
